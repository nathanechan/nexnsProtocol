# NEXNS 视觉升级 · Step 4 项目终端与操作流程

## 正式页面

Curve、Migration、Operating 共用 `terminal-surfaces.css`。已将原预览终端样式迁入正式组件，预览保留评审工具栏，不再独立维护另一套终端样式。

- 页头保持简称在前、全称在后；名称下不显示 `/USDT`。保留合约、必要安全状态、分享。
- 桌面采用图表/详情与操作面板双区，取消常驻项目侧栏。
- “切换项目”按需打开原有项目列表，保留生命周期筛选、当前项目标识与统一搜索。切换窗口交给搜索时先关闭自身，避免叠加两层弹窗。
- 手机按指标、图表、操作、详情排列；提供直达操作区锚点；分享入口收进顶部操作区。暂不可用的 DEX 按钮仅在桌面保留禁用展示。
- 手机 Curve 图表占满内容宽度；长名称保留截断与完整标题，金额输入使用清晰数字层级。
- Operating 图表沿用既有质押数据、时间范围、指针与键盘检查。金额、数量、价格均没有新增数据源。
- 迁移主区突出状态和时间线，隐藏不可用的运行指标；关闭交易与持仓展示保留，不增加强制迁移操作。

## 操作反馈

买卖、Participate、Stake / Unstake、Claim 沿用原有输入、校验、报价、确认和执行函数。没有改变金额、费用、收益、限额、结算或持久化。

- 表单减少原有固定最小高度和空白；参与、质押、领取使用紧凑统一基线以保留按钮对齐，手机操作标签继续吸顶，按钮、余额、预计结果沿用共享基础组件。
- Modal 新增可选 `footer` 与 `busy`，财务确认使用同一底部操作区；旧消费者不传参数时保持原有关闭方式。
- 处理中保留加载与 aria-busy，关闭按钮同步禁用；原有防重复执行、状态变化检查与关闭保护仍在。
- 处理中消息不再被呈现为错误；成功、失败继续使用原有文案和实际结果。
- 确认框保留项目、简称、合约、金额、预计结果和参与资金不可赎回提示，没有弱化必要限制。

## 验证

完整单元/集成测试覆盖生命周期切换、按需项目窗口、统一搜索事件及原有经济流程。旧终端浏览器断言改为验证新的按需切换窗口与操作区位置，不再要求常驻侧栏或旧屏幕坐标。

`scripts/terminal-step4-browser-check.mjs` 覆盖两种语言 × 1440 / 768 / 430 / 390 的 Curve、Operating，验证无溢出、双区/手机顺序、图表宽度、操作锚点、切换窗口、阶段筛选、搜索交接、确认身份、处理中关闭保护及真实成功反馈。另复跑旧的四生命周期、买卖、迁移、Operating、资产、领取、列表、自选、语言及实时估值检查。

证据输出到忽略目录 `test-results/terminal-step4/`。本轮结束停在 Step 4，剩余资产/创建/管理等页面的整体视觉推广属于 Step 5；未自动推送或部署。
