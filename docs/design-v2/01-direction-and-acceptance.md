# NEXNS 视觉重构 V2 · Step 1 对标与设计标准

日期：2026-10-18（Asia/Kuala_Lumpur）

状态：第 1 阶段交付，供第 2 阶段两套旗舰方案使用；尚非新页面实现或用户最终视觉批准。现有正式页面与经济逻辑没有修改。

## 1. 目标与产品边界

目标是提高视觉构图、品牌识别和核心任务完成质量。以用户认可的产品为参照，不承诺可客观评定的“行业第一”。HYPE 暂按 Hyperliquid、POLY 暂按 Polymarket 理解。

维持浅色、白/浅灰画布、海军蓝文字、品牌蓝强调。保持顶部导航与宽画布，不增加常驻重侧栏。品牌识别主要来自 Logo、排版、比例、图表和操作结构。

保持现有模拟数据与执行层；不改费用、参与不可赎回、收益、限额、结算、项目身份与搜索规则。不增加买回、LP、铸币、强制迁移、Oracle、财库执行按钮。图表必须标明实际数据类型，不能把质押趋势当作价格走势。

## 4. 当前版本的具体差距

基线：`be00135`。检查了当前 Operating 终端 1440×1000 与 390×844，以及资产页；结合组件源文件审查。

1. **Logo 不一致**：当前 `ProjectLogo` 的平台图形仍为蓝青渐变圆角方块白 N；正式资产为蓝色六边形 N。导航字标也没有复用正式字形。
2. **强调色分散**：当前基础强调为 `#4164ED`，图表为紫色，平台图标带青色。品牌蓝没有成为贯穿页面的稳定识别。
3. **身份到内容的纵向距离偏大**：桌面身份下方到数据区的留白较多，价格又在页头和指标条重复，第一屏空间没有集中支持图表和动作。
4. **表单留白缺少信息用途**：为跨标签按钮稳定而保留的固定高度，导致金额/余额与确认之间大片空白；需重新设计共同结构，保留稳定性但不单靠空高实现。
5. **指标卡片同权重**：价格、总质押、价值、流动性、人数视觉接近，且部分重复；主数字、支撑证据与个人资产的层级不足。
6. **手机首屏看不到操作表单**：390×844 基线先显示身份、五指标、较高图表，实际参与区在下方；“操作↓”只能缓解，不能替代首屏主动作设计。
7. **图表外围说明较弱**：有图形但辅助字偏小，时间与数据读数占位散，紫色填充与品牌不一致。现有模拟历史可有平台段，不能为了视觉擅改数据。
8. **容器重复**：圆角白卡、细线与背景大量重复，模块都像独立小工具；需要一套更连续的主画布与更聚焦的操作表面。
9. **文案语义未完全统一**：Token资产、中英文 N/A、重复结果说明仍需按数据场景清理。不得统一替换未知数据为零。

## 5. 旗舰页的信息层级

第一层：项目 Symbol、次级 Name、当前阶段/影响操作的异常、简短可复制合约与价格；同一个价格不在邻近位置重复强调。

第二层：可信且有标签的核心项目趋势、精简项目指标、明确的用户操作区。

第三层：用户当前仓位/质押/可领取与所选动作有关的余额、预计结果、确认主按钮。

第四层：仓位记录、收益历史、邀请、公开结果与项目资料；使用分类、展开或下方区域承载，不平铺成主屏说明书。

当 Claim 被选中时，主界面展示可领取、输入金额、到账、估值、状态与历史入口。Participate 确认保留资金不可作为本金赎回的警告。状态变化不改变按钮语义或吞掉实际执行结果。

## 6. 两套方案的设计任务（Step 2）

两套都使用相同正式 Logo、数据样例、功能和品牌色。区别必须来自构图和任务组织，不能只换背景色。

**A · 数据工作台**：连续主画布、紧凑身份与指标行、宽图表、右侧固定宽操作区；较少外层容器，适合频繁查看项目。手机以紧凑摘要、明确动作入口和可折叠图表组织，验证进入操作所需步骤。

**B · 操作聚焦**：身份与价格更集中，操作表面更突出，图表及项目数据作为相邻支持区；个人余额、预计结果围绕当前动作展开。手机优先让用户接触金额与主动作，同时保留趋势入口。

共同交付：每套 1440px 桌面、390px 手机的高保真画面；同一 Operating 项目、相同数字、相同参与态；另展示有可领取、无历史/异常价格各一个代表状态。两套不得提供后端控制，不能用虚构专业图表掩盖缺失数据。

## 7. 排版与组件起点

- 正文 14–16px，辅助说明 12–13px；10–11px 仅用于稀疏刻度/次要元数据，不能承载核心金额、风险提示和操作。
- 项目标题 24–28px；主要数据/输入 30–40px；次级指标 16–20px。数字使用 tabular-nums，数量、价格、USDT 单位有不同的格式约定。
- 控件高度 44–48px，桌面次级工具可紧凑但需保证目标可点击。图标按钮需名称、焦点与足够点击区域。
- 间距用 4/8/12/16/24/32px 家族；圆角按角色约 8/12/16px，避免所有块都使用同一大圆角。
- 系统中英文字体先保证可读性；是否引入品牌字体由两套方案实测，未审核字体授权前不新增下载依赖。
- 不用动画造成数字跳动、按钮移位和误触；交互反馈优先颜色/透明度，减少动态效果时仍能理解状态。

这些是起始标准，Step 3 实现和 Step 4 系统定型前允许调整，不立即覆盖当前 CSS。

## 8. 审核标准与阶段闸口

| 维度     | 审核方式/通过条件                                                            |
| -------- | ---------------------------------------------------------------------------- |
| 主次     | 评审者第一眼能指出项目身份、核心数据和主操作，不需解释每个卡片               |
| 品牌     | 源 Logo 几何/比例正确，品牌蓝一致，品牌识别不靠额外装饰                      |
| 语义     | 名称/简称、链+合约身份、币种单位、未知/零值和生命周期正确                    |
| 任务     | 搜索→进入项目、参与→质押、收益→领取不新增无意义步骤；失败可恢复              |
| 手机     | 在 390×844 可找到并进入主动作；320px 不横向溢出；实际输入、确认与底栏不冲突  |
| 内容压力 | 中英、长名称/符号、重复名称、空/零/大额、禁用、处理中、错误、迁移均有设计    |
| 可访问   | 普通文字对比度至少 4.5:1，关键 UI/图形按角色检验 3:1；键盘焦点与减少动效可用 |
| 一致性   | 同一动作的名称、金额格式和反馈跨页一致，不靠覆盖层层 CSS 偶然实现            |

Step 2 两套高保真需由用户选择/修正方向；Step 3 可交互旗舰需实际审核，通过后才提炼设计系统并推广全站。自动化回归是功能和技术底线，不能替代审美与任务测试。实体手机状态仍需实机验收。
