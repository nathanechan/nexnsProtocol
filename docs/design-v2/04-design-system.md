# Step 4 · 设计系统 V2 定型

适用基础：用户确认的桌面 A / 手机 B 旗舰。此阶段建立实现标准，未将全部页面重新排版。独立可查看规范为 <http://localhost:3002>，只读服务器脚本 `scripts/design-v2-system-server.mjs`；它直接提供产品的基础 CSS 与 V2 CSS，没有复制样式文件。

## 文件与职责

| 文件                              | 职责                                                                     |
| --------------------------------- | ------------------------------------------------------------------------ |
| `src/app/design-system.css`       | 现有 Button、Input、Modal、focus、loading、disabled 基础行为与基础样式   |
| `src/app/system-v2.css`           | V2 品牌、语义色、字号/间距/圆角/阴影角色；V2 控件状态与轻量表面/提示用法 |
| `src/app/flagship-terminal.css`   | 旗舰几何、桌面 A / 手机 B 排列；不再单独维护一份 V2 品牌变量             |
| `src/components/brand-mark.tsx`   | 正式六边形 N 的唯一 React 图形实现                                       |
| `src/components/project-logo.tsx` | 复用品牌组件，保留平台有效上传图与普通项目自定义 Logo 规则               |
| `docs/design-v2/04-system.html`   | 实现参考和状态演示，金额为示例，不调用任何资产执行接口                   |

## 采用方式

旗舰通过 `.terminal-flagship` 采用 V2。其他页面在 Step 5 可将 `data-nexns-ui="v2"` 放在页面容器；样式会通过 body 的 :has 选择器同步主题，使 Radix 传送到 body 的弹窗也获得相同变量。也可在独立规范页 body 上直接使用该属性。

未采用 V2 的页面保持原样，不能靠全局替换所有颜色、卡片与布局实现迁移。旧色值留给尚未升级的页面，V2 的品牌定义只来自共享文件。

现有 `Button` 保留 `variant`、`loading`、`disabled` API；`Input` 保留原生属性；`Modal` 保留 `busy`、`footer`。本阶段不另建一套金融表单、不修改事件、费用、验证、执行或持久化。

## 品牌与语义角色

| 角色                | 值                    | 用途                                   |
| ------------------- | --------------------- | -------------------------------------- |
| accent              | `#2464EB`             | 原 SVG 品牌蓝，主操作/选中/关键交互    |
| ink                 | `#101B32`             | 原 SVG 海军蓝，内容与重要数字          |
| secondary / muted   | `#526176`             | 辅助说明，不使用低对比浅灰承载关键内容 |
| canvas / surface    | `#F6F8FB` / `#FFFFFF` | 画布与操作表面                         |
| line / control-line | `#E5EAF1` / `#CAD6E8` | 结构分隔 / 可操作边界，角色不同        |
| success             | `#23785F` / `#EAF5EF` | 实际成功结果与正向状态                 |
| danger              | `#A43143` / `#FFF2F4` | 错误与负向反馈                         |
| warning             | `#735524` / `#FFF9EF` | 不可逆或需要注意的信息                 |

普通项目品牌不重新染色；不把 N/A/未知改成零；不靠颜色独自表达风险或成功。示例图表不能进入真实数据层。

## 排版与空间

- 标题 28px，主数据 30px，正文 14px，辅助 12px。手机标题、金额、极少量刻度仍按具体角色做响应式调整；普通输入至少 16px，金额输入可更大。
- 数字使用 tabular-nums；数量与资产单位保持关联。tabular-nums 不保证位数增加时永不换行；长名称、长符号和大金额仍需压力验证。
- 间距族 4 / 8 / 12 / 16 / 20 / 24 / 28 / 32px。
- 主面板 12px、输入 10px、主要按钮 8px、轻提示 6px 圆角。不是所有内容都需要外层卡片。
- 主要按钮 48px；次级按钮沿用现有基础尺寸和手机规范，紧凑工具入口按角色保留，但不能只缩小字来容纳内容。

## 组件状态

主要、次要、ghost、hover、pressed、focus、disabled、loading 均沿用现有可访问语义；加载禁止重复执行，文字仍可读。静态示例中的 1.2 秒等待只用于规范页，不是产品执行时间。

输入错误绑定 `aria-invalid` / `aria-describedby`，错误说明恢复方法。确认弹窗支持焦点和 Escape，真实处理中继续沿用原有关闭保护。风险提示继续在最终确认展示，不因视觉简化删除。

`nx-surface`、`nx-label`、`nx-value`、`nx-notice[data-tone]` 是可采用的视觉角色，规范页展示实际 CSS 用法。真正的数据与财务操作继续调用现有业务组件。

## 验收与后续

完整单元测试、规范页 1440/768/390/320 的状态/溢出/减少动效/对比度检查；旗舰真实表单、可领取状态、标签位置、桌面 A / 手机 B、品牌路径回归。正式预览关闭测试控制入口后重新检查。

规范页的对比度检测覆盖主按钮与成功/错误/风险提示正文，不等于全站可访问认证。静态规范页复用实际 CSS 与 DOM 约定，真实 React 组件由单元和旗舰浏览器检查覆盖。未实机验收软键盘。

下一阶段 Step 5 才将共享系统推广到发行、运行、资产、创建、工作室、协议和 NEXNS 页面，并逐页审核信息密度与文案。未推送仓库。
