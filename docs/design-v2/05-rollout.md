# Step 5 · 全站推广与信息精修

基于已确认的 V2 共享系统，正式页面采用 `data-nexns-ui="v2"`。发行/运行/市场、资产、创建、工作室、协议、NEXNS 核心资产与各生命周期项目页使用同一品牌角色；body 主题同步到共享导航、搜索和确认弹窗。页面几何集中在 `src/app/pages-v2.css`，Operating 旗舰仍由旗舰样式负责。

## 页面取舍

| 页面              | 本轮改变                                                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发行 / 运行       | 标题配简短阶段标签、下划线分类、平静的列表表面；品牌蓝用于选中/进度/自选，涨跌保持语义色。排序、自选、搜索、价格、行结构与路由不变。              |
| 资产              | “代币资产”作为主要摘要，仓位/质押/领取/项目保持五项口径；强调有余额的领取入口，移除每行重复的“可领取”小标签；空领取状态保持独立且不显示矛盾标题。 |
| 创建              | 单一表单主线、清晰步骤、统一输入与主要按钮；规则仍可展开；未填写简介时不显示占位段落，不改用户内容保存。                                          |
| 工作室            | 标题简化为“工作室”，项目 Logo、Symbol/Name、注册 ID、阶段和合约集中于身份行。指标形成一个摘要表面，详情按内容高度排列，去除重复的财库只读说明。   |
| 协议              | 标题辅助说明缩为“合约、供应与结算”；地址缺失显示“暂无地址”，不虚构池合约。原六模块与分页保持。                                                    |
| NEXNS             | 双区概览保持资产与角色层级；无生态连接时明确说明，不留下无内容卡片。连接筛选条件不变。                                                            |
| Curve / Migration | 采用共享品牌、控件和面板角色；曲线图线色与进度改为品牌蓝，不改曲线数据、毕业与迁移体验。Operating 保留桌面 A / 手机 B。                           |

## 文案记录

- Token资产 → 代币资产；英文 Assets → Token assets，明确摘要范围。
- 缺失的个人记录时间 N/A → 暂无记录 / No records yet。
- 协议合约表缺失池地址 N/A → 暂无地址 / Address unavailable。
- “当前为公开分析视图。仅创建者钱包可以更新 Logo 与链接。” → “仅创建者可编辑项目资料。” / “Only the creator can edit project details.”
- “项目身份、供应、结算与流动性的公开结果。” → “合约、供应与结算。” / “Contracts, supply and settlements.”
- 创建确认的“暂无描述”空段落移除；现有简介按原文本显示。
- 没有全局将未知值替换为零；估值、覆盖、奖励和其他数据口径保持原读模型。其余技术占位符按场景保留，不宣称已逐字重写全部产品文案。
